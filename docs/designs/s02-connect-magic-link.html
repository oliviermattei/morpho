s02-connect-magic-link — maquette de référence

Connexion sans mot de passe. Trois écrans : la connexion, l'état « lien envoyé », et le placeholder authentifié. Cadres à 375 px, la cible du critère d'acceptation. Chaque état est rendu en clair et en sombre ; la planche elle-même suit le thème système.

Référence, pas du code. Les classes reproduisent à la main le rendu du preset radix-nova pour que le fichier soit autonome. /ks-execute construit avec les vrais composants : npx shadcn@latest add button input field spinner alert empty.

Tailles rendues : celles du preset, relevées au registre — input et button en h-8 (32 px). C'est sous les 44 pt recommandés par iOS : le design system gap n°5 est ouvert, la maquette ne préempte pas la décision.

1 — Écran de connexion · état initial

Un champ, une action. Aucun lien « créer un compte », aucun « mot de passe oublié », aucun fournisseur tiers. Le focus est posé à l'arrivée : le clavier système s'ouvre sans geste.

L'anneau de focus visible est celui du preset (--ring, 3 px). Le champ est en 16 px (text-base md:text-sm) : c'est ce qui empêche iOS Safari de zoomer au focus. Ne pas le forcer en text-sm.

2 — Écran de connexion · erreur de champ

Erreur de validation : message sous le champ, jamais un résumé en haut de page (§ Patterns UI). L'input passe en aria-invalid — bordure et anneau --destructive sont fournis par le preset, l'écran ne pose aucune couleur.

3 — Écran de connexion · chargement (envoi en cours)

Spinner dans le bouton, jamais en plein écran. Champ et bouton désactivés. Le libellé passe à « Envoi… » : le bouton est pleine largeur, donc aucun saut de mise en page. Franciser l'étiquette accessible au point d'appel — <Spinner aria-label="Chargement" /> — sans jamais éditer le fichier généré.

4 — Écran de connexion · échec de l'envoi (erreur d'opération)

Cette erreur n'appartient à aucun champ : la mettre sous l'email mentirait sur sa cause. Traitement alert variant destructive, en tête de formulaire — voir design system gap n°2. Le champ conserve sa valeur : rien à retaper.

5 — Écran de connexion · lien expiré ou déjà utilisé

Répond à la note de story « prévoir le cas du lien expiré ou déjà consommé : un message clair, pas une page blanche ». L'utilisateur arrive ici par redirection : l'app ne connaît plus son adresse, le champ est donc vide. Message en français, sans code technique.

6 — État « lien envoyé » · succès

Pas un toast. L'utilisateur quitte l'app pour son client mail : le message doit survivre au retour. Composé avec empty (média + titre + description + actions) — voir design system gap n°3. « Utiliser une autre adresse » est requis : sans compte ni mot de passe, une faute de frappe est sinon un cul-de-sac. « Renvoyer le lien » est optionnel.

Adresse en overflow-wrap: anywhere : une adresse longue se coupe au lieu de déborder du viewport à 375 px.

7 — État « lien envoyé » · renvoi en cours, puis renvoi échoué

Le Spinner reste dans le bouton concerné ; les deux actions se désactivent ensemble. En cas d'échec, l'alert se pose au-dessus du bloc : l'état « lien envoyé » n'est pas perdu.

8 — Écran authentifié provisoire

Placeholder assumé — ne pas y investir de design. docs/stories.md l. 64 : s06 le remplace intégralement par la silhouette. Ce qui suit est le strict nécessaire pour rendre les critères de session testables : l'email connecté et la déconnexion. Aucun composant supplémentaire n'est installé pour cet écran.

Pas de card, pas d'avatar, pas de menu utilisateur, pas de squelette : la page est un Server Component qui dispose déjà de la session au rendu. Le châssis authentifié réel se décide en /ks-design s06 — design system gap n°7.

9 — Transitoire de retour du lien · conditionnel

Dans le cas nominal, aucun écran n'est rendu : le proxy pose les cookies et redirige vers /. Ce rendu n'existe que si une route de callback visible se révèle nécessaire (docs/research/s02-connect-magic-link.md § Open questions 2, non tranché). C'est le seul cas où un chargement occupe l'écran — parce qu'il n'y a aucun contenu à esquisser.

Rappel — ce que cette maquette ne décide pas

Les design system gaps sont énumérés dans docs/designs/s02-connect-magic-link.md. En résumé : field/label/alert/empty sont tabulés à d'autres stories que s02 (lignes de tableau à corriger, les composants existent bien) ; aucune icône n'est encore attribuée à une action ; aucune taille de cible tactile minimale n'est définie alors que les défauts du preset sont à 32 px ; aucun mot-symbole n'est arrêté ; et la classe .dark n'est posée par personne aujourd'hui, ce qui rend la colonne « sombre » de cette planche invérifiable dans l'app réelle tant que le shell ne la livre pas. Rien de tout cela n'a été tranché ici.
