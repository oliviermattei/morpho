# Plan — Story s04-profile-height-bmi

Branch: `feature/s04-profile-height-bmi`, tirée de `feature/s03-log-measurement-session` (ou de la branche par défaut si s03 y est déjà mergée). Voir §Préconditions.

## Target story

**As a** utilisateur **I want** renseigner ma taille une fois **so that** mon IMC se calcule tout seul à chaque pesée. — Complexity 2.

Critères d'acceptation (verbatim `docs/stories.md`) :

1. Un écran de profil permet de saisir et de modifier une taille en centimètres, persistée et rattachée à l'utilisateur.
2. Tant que la taille n'est pas renseignée, l'IMC n'est affiché nulle part, et l'app invite à la renseigner au lieu d'afficher une valeur vide ou fausse.
3. Une fois la taille renseignée, chaque session comportant un poids affiche un IMC calculé (`poids_kg / taille_m²`), arrondi à une décimale.
4. L'IMC n'est jamais saisissable : aucun champ IMC dans le formulaire de s03.
5. L'IMC n'est pas stocké en base : modifier la taille de référence met à jour l'IMC de toutes les sessions passées, vérifié sur au moins deux sessions antérieures.
6. Une session sans poids n'affiche pas d'IMC.

Contraintes produit rattachées : l'IMC est **dérivé à la lecture, jamais persisté** ; la taille vit sur le profil, pas sur la session ; `profiles` doit accueillir le poids cible de s08 **sans devenir un système de préférences générique** ; **aucune classification** (« surpoids », « obésité ») — morpho affiche un nombre.

## La recherche est périmée sur deux points — à lire avant tout le reste

`docs/research/s04-profile-height-bmi.md` a été écrite le 2026-08-02 sur un dépôt où **rien** n'était implémenté. Deux de ses conclusions sont fausses aujourd'hui et un implémenteur qui la suivrait littéralement produirait du code faux :

| Affirmation de la research | État réel, vérifié |
|---|---|
| « `morpho/` est encore le scaffold brut de `create-next-app` » (l. 26) | **Faux.** s01 est livrée (shell conforme `lang="fr"` + script de thème, `getSql()`/`getDb()`, `getAuth()`, `/api/health`, `/api/session`, harnais Vitest + Playwright 375×812). s02 est en cours sur `feature/s02-connect-magic-link` (auth `sameSite: 'lax'`, handler, `src/proxy.ts`, écran de connexion). `src/components/ui/` contient déjà `alert`, `button`, `empty`, `field`, `input`, `label`, `separator`, `spinner`. |
| « `session.user.id` est une `string`, donc `profiles.user_id` doit être `text` … sauf si s02 établit le contraire » (l. 155) | **Contredit par la base réelle.** s02 a interrogé la base : la table est `neon_auth."user"`, PK `id` de type **`uuid`**. `users_sync` n'existe pas. `profiles.user_id` est un **`uuid`**. La research avait posé la bonne réserve ; s02 l'a levée. |

Restent valides et intégralement reprises ci-dessous : le piège `numeric` mode chaîne, le piège `z.coerce.number("")` → `0`, le format français, la source unique de calcul, `redirect()` qui lève, `src/components/ui/` généré, l'interdiction de `@vitejs/plugin-react`.

## Préconditions — bloquantes, fail-closed

s04 consomme des artefacts qu'elle ne produit pas. `/ks-execute` **ne démarre pas** si l'un manque ; il s'arrête et rend la main à l'orchestrateur.

1. **s02 mergée** — `getAuth().getSession()` doit rendre une vraie identité, et `src/proxy.ts` doit protéger `/profil`. Sans elle, « rattachée à l'utilisateur » n'a pas de sujet.
2. **s03 mergée** — quatre des six critères (3, 4, 5, 6) portent sur des surfaces livrées par s03. Sans s03, s04 ne peut livrer que sa fonction pure et son écran de profil, c'est-à-dire une demi-story ; le pipeline exige une story par PR, pas une moitié.
3. **`DATABASE_URL` visible par `drizzle-kit`** — `morpho/.env.local` peuplé **et** le correctif de `drizzle.config.ts` de s03 en place. ⚠️ *Première rédaction : « `morpho/.env.local` existe et la base répond », comme si cela suffisait. C'est faux, et mesuré : `drizzle.config.ts` fait `import "dotenv/config"`, qui ne lit que `.env` — fichier **absent** du dépôt (`.gitignore` ligne `.env*`, seul `.env.example` est versionné). Spike exécuté dans `morpho/` : après `require("dotenv/config")`, `process.env.DATABASE_URL` est `undefined` alors que `.env.local` le contient. `db:generate` ne le révèle pas (il ne se connecte pas) ; `db:migrate` échoue sur `Please provide required params for Postgres driver: [x] url: undefined`.* Le correctif — `config({ path: [".env.local", ".env"] })` — appartient à **s03, décision 17 / tâche 1**. s04 ne le refait pas ; elle vérifie qu'il est là avant de démarrer la tâche 5.
